## 2. Keyboard Navigation & ARIA (FAIL)

### 2a. Interactive elements without accessible names (index.html)

| Element | Issue | Fix |
|---------|-------|-----|
| `#mSolo` button | No aria-label or title; text content is "Solo" (visible) but no role context | Add `aria-pressed="true"` + `role="switch"` |
| `#mGroup` button | Same as above | Add `aria-pressed="false"` + `role="switch"` |
| `#actRefresh` button | No aria-label; likely has visible text "⟳" (icon only) | Add `aria-label="Refresh activity feed"` |
| `#gitCommit` button | No aria-label; likely icon-only or minimal text | Add `aria-label="Create git commit"` |
| `#intResume` button | No aria-label; dynamically created, no context | Add `aria-label="Resume interrupted run"` |

### 2b. Form inputs without accessible names (index.html)

| Input | Issue | Fix |
|-------|-------|-----|
| `#f_emoji` | No label, no aria-label, no placeholder | Add `aria-label="Agent emoji"` |
| `#f_color` | Color picker with no label | Add `aria-label="Agent status color"` |
| `#f_blurb` | No label or placeholder | Add `aria-label="Agent description"` |
| `#f_net` | Checkbox with no label | Wrap in `<label>` or add `aria-label="Network access"` |

### 2c. Dynamic content lacks live regions (ui/core.js)

- **No `aria-live` regions exist** — screen readers cannot announce new chat messages, status changes, or error toasts.
- **Fix:** Add `role="log" aria-live="polite"` to the message container (`#msgs` or equivalent).
- Add `role="status" aria-live="polite"` to any toast/notification area.

### 2d. Tab order / focus management

- Only 1 `tabindex` reference in core.js — likely fine for native elements, but:
- Modal dialogs (if any) should trap focus and return it on close.
- Check that all dynamically created buttons (3 in core.js, 3 in uploads.js) are keyboard-reachable.
