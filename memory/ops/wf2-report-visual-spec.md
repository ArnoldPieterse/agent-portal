# WF2 Weekly Report — Visual Layout Spec
Created: 2026-11-26 | Designer lane
Serves: Builder (PDF implementation), Outlet (demo screenshots + pricing one-pager)
Depends on: stealth-output-spec.md (text content + tone), wf2_weekly_report.py (data shape)

## Purpose
The current WF2 output is machine-readable markdown. This spec defines the **client-facing visual layout**
for the weekly performance report that goes to SMB owners. It's the "hero moment" of the demo —
the one artifact that makes a prospect say "I want this running for my business."

## Canvas
- **Format**: PDF, A4 portrait (210x297mm), single page
- **Safe area**: 15mm margins all sides -> usable 180x267mm
- **Fallback**: if reportlab unavailable, emit HTML (weasyprint) with same layout; max-width 680px

## Zone Layout (top to bottom)

### Z1 — Header (height: 28mm)
| Element | Position | Spec |
|---------|----------|------|
| Business logo placeholder | left, top | 24x24mm square, rounded 3mm; grey #e5e7eb if no logo |
| "Weekly Performance Report" | right of logo, baseline-aligned | 18pt semibold, color #1a1a2e |
| Week range subtitle | below title | 11pt regular, color #6b7280; format: "Week of Mon 10 Nov - Sun 16 Nov" |

### Z2 — KPI Row (height: 35mm)
Three equal-width cards (54mm each, 9mm gaps):

| Card | Content | Color Rule |
|------|---------|------------|
| Revenue | $X,XXX total + WoW delta badge | Badge: green #059669 if >0, red #dc2626 if <0, grey #6b7280 if flat |
| Tickets Closed | count + trend arrow (up/down/flat) | Arrow color same rule as revenue badge |
| Anomalies | count of flagged metrics (or "None") | 0 = green check; >0 = amber #d97706 bold |

Card style: white bg, 1px border #e5e7eb, rounded 4mm corners, padding 8mm.
Metric name: 10pt uppercase tracking-wide #6b7280. Value: 22pt semibold #1a1a2e.

### Z3 — Metric Table (variable height, min 60mm)
Standard table, one row per metric:

| Column | Width | Align |
|--------|-------|-------|
| Metric name | 45% | left |
| This week avg | 20% | right |
| Last week avg | 20% | right |
| WoW delta | 15% | right, colored badge |

Row height: 10mm. Alternating row bg: white / #f9fafb.
Header row: 10pt semibold #374151, bottom border 1px #d1d5db.
Data rows: 11pt regular #1a1a2e.

Anomaly rows: left border 3mm solid #dc2626; metric name in bold; "ANOMALY" tag after value in red 9pt.

### Z4 — Anomaly Callout (height: 25mm, conditional)
Only renders if >=1 anomaly detected. If none: skip zone entirely (table extends).

Style: left-bordered block (3mm solid #f59e0b), bg #fffbeb, padding 8mm.
- Title: "Attention needed" — 12pt semibold #92400e
- Body: one sentence per anomaly, 11pt #78350f. Max 3 lines; overflow -> "See full report for details."
- CTA hint (bottom-right): "Reply 'details' to this email for the full breakdown" — 9pt italic #b45309

### Z5 — Footer (height: 20mm)
- Left: "Auto-generated by {{business_name}} - Week {{week_number}}"
- Right: ref_id in mono 8pt #9ca3af
- Top border: 1px solid #e5e7eb separating from content

## Data Binding (JSON -> zones)
The report generator emits this intermediate JSON; the PDF renderer consumes it:
```json
{
  "meta": {"business_name": "Acme Co", "week_range": "2026-11-10..2026-11-16", "generated_at": "..."},
  "kpis": [
    {"label": "Revenue", "value": "$4,230", "delta_pct": 12.4, "direction": "up"},
    {"label": "Tickets Closed", "value": "47", "delta_pct": -3.1, "direction": "down"},
    {"label": "Anomalies", "value": "1", "direction": "flag"}
  ],
  "table": {
    "columns": ["Metric", "This Week", "Last Week", "WoW"],
    "rows": [
      {"metric": "Revenue", "current": "$4,230", "prior": "$3,763", "delta": "+12.4%", "anomaly": false},
      {"metric": "Avg Response Time", "current": "4.2h", "prior": "3.8h", "delta": "+10.5%", "anomaly": true}
    ]
  },
  "anomalies": [
    {"metric": "Avg Response Time", "detail": "Response time up 10.5% - outside 2-sigma band for trailing 30 days."}
  ],
  "footer": {"business_name": "Acme Co", "week_number": "46", "ref_id": "rpt-2026-w46-abc123"}
}
```

## Color Palette (fixed, not theme-aware - this is a client artifact)
| Token | Hex | Usage |
|-------|-----|-------|
| --ink | #1a1a2e | Primary text |
| --muted | #6b7280 | Secondary text, labels |
| --border | #e5e7eb | Card borders, table lines |
| --row-alt | #f9fafb | Alternating table rows |
| --ok | #059669 | Positive deltas, "no anomalies" |
| --err | #dc2626 | Negative deltas, anomaly borders |
| --warn | #d97706 | Anomaly count badge, callout border |
| --callout-bg | #fffbeb | Anomaly callout background |
| --callout-text | #92400e / #78350f | Callout title / body |

These are NOT the cockpit design tokens - they're fixed for the client-facing artifact.
No theme switching. Always light.

## Implementation Notes for Builder

  1. Computes the same data as today
  2. Emits the intermediate JSON above to stdout (or `--json-out` path)
  3. If `--render-pdf`, pipes that JSON through reportlab/weasyprint using this spec
- Selftest: render a sample PDF, assert page count == 1, assert no overflow (all zones fit in 267mm usable height with max 8 table rows)
- Keep the markdown output as-is for internal use; PDF is the client-facing layer

## Verification Checklist
- [ ] Single A4 page, no overflow at 8 metrics max
- [ ] KPI cards equal width, no text truncation
- [ ] Anomaly row has visible left border + tag
- [ ] Callout zone collapses cleanly when 0 anomalies (no empty gap)
- [ ] All colors match palette above (run pdf2image -> pixel sample if needed)
- [ ] Font renders correctly (no tofu boxes for arrow/warning/check glyphs)
- [ ] File size < 200KB (no embedded images beyond logo placeholder)

## Handoff to Outlet
- **Demo script hero moment**: open this PDF on a phone screen (rotate to portrait), scroll past KPI row to the anomaly callout - that's the "oh, it caught that for me?" beat.
- **Pricing one-pager**: screenshot Z2+Z3 as the "here's your weekly report" visual. Crop at 680px width for social posts.
- **Tone match**: the visual is clean/data-forward; Outlet copy should be warm but not gushing. The report speaks for itself - let the anomaly callout do the selling.

## Anti-Patterns (do NOT)
- No charts/graphs on v1 (keep it table-based; adds dependency weight + complexity)
- No dark mode variant (client opens on phone in daylight)
- No more than 8 metric rows visible; overflow -> "See full report" link
- No decorative elements beyond the zone borders and badges
- No animation (it's a PDF, not a web page) - save that for the interactive demo if needed later
