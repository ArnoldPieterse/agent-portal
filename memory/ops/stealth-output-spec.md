# Stealth Workflow — Client-Facing Output Spec
Created: 2026-11-26 | Designer lane (contribution to Builder deployment + Outlet demo pack)
Purpose: Define what the client actually SEES for each workflow. Current outputs are
machine-readable (JSON/MD); this spec defines the presentable layer that makes them sellable.

## Design Principles
- **Scannable in <15s**: client is busy; key signal must hit immediately
- **One CTA max** per message: single action, no choice paralysis
- **Consistent voice**: professional but warm (not corporate-cold, not casual)
- **Mobile-first**: 80% of SMB owners read on phone; line length <= 60 chars

## WF1 — AR Follow-Up Reminders (email + SMS)

### Tier 1: Day 7 (Friendly Nudge)
**Subject:** Quick reminder — invoice {{invoice_id}} due {{due_date}}
**Body (email):**
```
Hi {{first_name}},

Just a friendly nudge that invoice #{{invoice_id}} for ${{amount}} was due on {{due_date}}.

If you've already sent payment, please disregard this note.
Otherwise, you can pay via your usual method and we'll mark it as received.

Thanks!
{{sender_name}} — {{business_name}}
```
**SMS (<=160 chars):**
"Hi {{first_name}}, friendly reminder: invoice #{{invoice_id}} (${{amount}}) was due {{due_date}}. Reply 'paid' if sent. — {{business_name}}"

### Tier 2: Day 14 (Firm but Polite)
**Subject:** Invoice {{invoice_id}} now 14 days overdue — action needed
**Body (email):**
```
Hi {{first_name}},

Following up on invoice #{{invoice_id}} (${{amount}}), now 14 days past due.

We'd like to resolve this quickly to avoid any disruption to your account.
Please confirm payment status by {{response_deadline}}.

If there's an issue with the invoice, reply and we'll sort it out today.

Regards,
{{sender_name}} — {{business_name}}
```
**SMS:** "Hi {{first_name}}, invoice #{{invoice_id}} (${{amount}}) is 14 days overdue. Please confirm payment by {{response_deadline}}. — {{business_name}}"

### Tier 3: Day 21 (Escalation)
**Subject:** Final notice — invoice {{invoice_id}} (${{amount}}) 21 days overdue
**Body (email):**
```
Hi {{first_name}},

This is a final reminder for invoice #{{invoice_id}} (${{amount}}), now 21 days past due.

If payment has not been arranged, please contact us by {{final_deadline}} to discuss options.
After this date, the account may be referred for further collection action per our terms.

We'd prefer to resolve this directly — reply to this email and we'll make it easy.

{{sender_name}}
{{business_name}}
```
**SMS:** "Final notice: invoice #{{invoice_id}} (${{amount}}) is 21 days overdue. Please contact us by {{final_deadline}}. — {{business_name}}"

### Design Notes
- Tone escalation: friendly → firm → formal (never aggressive)
- Amount always in plain dollars, no decimals unless < $10
- Always give an "out" ("if already paid, disregard")
- CTA is implicit (pay/confirm), never a button or link in SMS

## WF2 — Weekly KPI Report (email + PDF)

### Email Template (what the client gets Monday 8am)
**Subject:** Your weekly report — {{week_range}} ({{anomaly_count}} flags)

```
Good morning {{first_name}},

Here's your week at a glance:

┌─────────────────────────────────────────────┐
│  METRIC          │  THIS WEEK  │  CHANGE   │
├─────────────────────────────────────────────┤
│  Revenue         │  ${{val}}    │  ▲ +{d}%  │
│  Tickets closed  │  {{val}}     │  ▼ -{d}%  │
│  New leads       │  {{val}}     │  — flat   │
│  Avg response    │  {h}h {m}m   │  ▲ +{d}%  │
└─────────────────────────────────────────────┘

{{#if anomalies}}
⚠️ FLAG: {{metric}} is {n}σ above normal — worth a look.
{{/if}}

Full report attached (PDF).

— Automated by {{business_name}} ops
```

### PDF Report Structure (1 page max)
1. **Header**: Business name + week range + "Generated by [product]"
2. **KPI Table**: up to 6 metrics, sorted by importance (revenue first)
   - Column: metric | this week | last week | Δ% | trend arrow | anomaly flag
3. **Anomaly Callout** (if any): single highlighted box, 1-2 sentences context
4. **Footer**: "Next report: {{date}}" + product watermark

### Visual Tokens (for future PDF renderer)
| Token | Value | Use |
|-------|-------|-----|
| --color-up | #0d7a3f | positive delta |
| --color-down | #c0392b | negative delta |
| --color-flat | #6b7280 | no change |
| --color-anomaly | #f59e0b | anomaly flag bg |
| --font-body | system-ui, 14px | table + body |
| --font-header | system-ui bold, 18px | title |
| --spacing-cell | 12px 16px | table padding |
| --max-width | 700px | report width |

### Design Notes
- Table over prose: clients scan numbers, not paragraphs
- Max 6 metrics; if more, group into "Other" with total
- Anomaly = single callout, NOT a separate section (keeps it 1 page)
- Trend arrows: ▲ ▼ — (consistent with current WF2 output)
- PDF is the deliverable; email is the wrapper/teaser

## WF3 — Appointment/Task Reminders (SMS + calendar push)

### SMS Template (48h before)
"{{first_name}}, you have {{event_type}} on {{day_name}} at {{time}} with {{other_party}}. Reply R to confirm, C to cancel. — {{business_name}}"

### SMS Template (2h before)
"Reminder: your {{event_type}} is in 2 hours ({{time}}). Location: {{location}}. Need to reschedule? Reply C. — {{business_name}}"

### Calendar Push (ICS summary field)
"{{event_type}} with {{other_party}}"
**Description:** "Auto-scheduled by {{business_name}}. Ref: {{ref_id}}"

### Design Notes
- SMS must fit in 1 segment (160 chars) including business name
- Always include a reply keyword (R/C) for zero-friction response
- Time format: 12h with am/pm (SMB audience, not 24h)
- No URLs in SMS (looks like spam); use "reply R" pattern

## Cross-Workflow Consistency Rules
1. **Brand block**: every output ends with `— {{business_name}}` (em-dash prefix)
2. **Name format**: first name only in body, full name in signature
3. **Currency**: $X,XXX (no decimals >= $10; $X.XX for < $10)
4. **Date**: "Mon 16 Dec" format (day name + day + month short)
5. **Tone register**: professional-warm. No exclamation marks except Tier 1 WF1.
6. **Length budget**: email body <= 120 words; SMS <= 160 chars; PDF = 1 page

## Implementation Notes for Builder
- Templates are Jinja2-compatible ({{var}}, {{#if}} blocks)
- Keep in `memory/builder/stealth/templates/` as .txt files per workflow/tier
- WF2 PDF: use reportlab or weasyprint; spec above is the layout contract
- Delivery layer (email/SMS API) is out of scope for this pass — output is the formatted string
- Selftest should validate: all {{vars}} present in template, no empty strings after render
