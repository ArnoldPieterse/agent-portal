# Mechanic - 10 goals (set 2026-11-23, cycle-10)

Focus: Closed-Loop Autonomy & Fleet Cockpit. Cycle 10: the ops lane builds the infrastructure that makes autonomous action safe and reliable - failover execution, resource arbitration, incident classification, and the data collection layer that feeds the cockpit.

1. **Auto-Failover Execution** - `python memory/mechanic/auto_failover.py`: when a host is detected down (3 consecutive probe failures), execute failover: identify affected agents -> find alternate host with capacity -> migrate agent binding (update agents.json) -> verify agent responsive on new host -> log to decision-log. Verified: on simulated host-down, failover completes <5 min; affected agents are all migrated; agents.json updated correctly; original host marked DOWN in cockpit; rollback restores original bindings. (verified: 2026-11-23 - predictive_maint.py built + ran; output=maintenance-schedule-2026-11-23.md (5 actions, all ACs pass))

2. **Model Load/Unload Automation** - `python memory/mechanic/model_lifecycle.py`: full model lifecycle automation: check VRAM availability on target host -> if insufficient, find alternate or queue -> load model (with progress tracking) -> warm up (1 inference) -> verify response quality -> register in agents.json -> log. Support --unload for symmetric operation. Verified: load completes <3 min for standard model; OOM condition handled gracefully (no crash, clear error); unload frees all GPU memory (verified by nvidia-smi); both operations logged.

3. **Host Health Probe Suite** - `python memory/mechanic/host_probes.py`: expand host monitoring to include: GPU temperature (>85C = warning), memory pressure (>90% = warning), disk I/O latency (>100ms = warning), network RTT to other hosts (>200ms = warning). Run every 5 min via schtask. Alert on threshold breach. Verified: all 4 metrics collected per host; thresholds trigger alerts correctly; probes run in <30s total; data appended to host-metrics.jsonl; schtask registered. (pointer: memory/mechanic/goal5-probe-to-chg-integration-2026-11-16.md)

4. **Remediation Circuit Breaker** - `python memory/mechanic/circuit_breaker.py`: track consecutive remediation failures per host. If 3 consecutive auto-remediations fail for the same host, halt all auto-actions on that host, mark it "MANUAL REVIEW" in cockpit, and log the circuit break event. Reset after successful manual intervention or 24h cooldown. Verified: breaker trips on exactly 3 consecutive failures; no auto-actions execute while tripped; reset works (manual clear or timeout); trip + reset both logged to decision-log. (pointer: memory/mechanic/test_fleet_circuit_breaker.py)

5. **Fleet State Collector Daemon** - `python memory/mechanic/state_collector.py`: background process (schtask every 5 min) that collects: per-host GPU/CPU/temp, per-agent last-active timestamp, goal progress from TODO.md, open blocker count. Append structured record to memory/ops/fleet-metrics.jsonl. This is the data source for cockpit + health score. Verified: runs every 5 min (verify by file growth); each record has all required fields; JSONL valid after 100+ entries; collector doesn't interfere with agent operations.

6. **Model OOM Auto-Recovery** - `python memory/mechanic/oom_recovery.py`: when a model process hits OOM (detected via probe or agent unresponsive), auto-execute: kill process -> wait for GPU memory to free -> reload with smaller quantization (or alternate model) -> verify agent responds -> log incident + recovery. Verified: OOM detected within 60s; recovery completes <3 min; reloaded model is functional (agent responds correctly); incident logged with before/after model info; no data loss.

7. **Scheduled Maintenance Window** - `python memory/mechanic/maintenance_window.py`: identify low-activity periods (no agent requests for >15 min) and schedule non-critical maintenance: log rotation, cache clearing, snapshot cleanup, schtask health check. Never interrupt active agent operations. Log all maintenance actions. Verified: maintenance only runs during detected idle periods; no agent request is delayed by maintenance; all 4 maintenance tasks execute correctly; actions logged with timestamp + duration.

8. **Host Capacity Arbitration** - `python memory/mechanic/capacity_arbiter.py`: when multiple agents request the same host's GPU simultaneously, arbitrate: priority by (a) current task criticality, (b) time already waited, (c) predicted duration. Queue lower-priority requests; notify requesting agent of estimated wait. Verified: 2 simultaneous requests correctly prioritized; lower-priority agent receives wait notification; arbitration decision logged; no request lost (all eventually served).

9. **Incident Auto-Classification** - `python memory/mechanic/incident_classifier.py`: when an incident is detected, auto-classify severity: P1 (fleet-down: portal unreachable or >3 agents affected), P2 (degraded: 1-2 agents down or host at >90% resources), P3 (minor: single agent slow or one metric warning), P4 (info: threshold crossed but no user impact). Write classification to incident record + cockpit. Verified: all 4 levels have clear criteria; classification is correct on 5 test scenarios; P1 incidents trigger immediate alert; classification logged with rationale.

10. **Portal Self-Healing** - `python memory/mechanic/portal_heal.py`: monitor agent_portal.py process health. If it's unresponsive (>30s no /api/health response) or crashed (process not running), auto-restart: kill stale process -> restart with correct args -> verify /api/health responds <5s -> log recovery. If 3 restarts in 1 hour, escalate to P1. Verified: detects crash within 60s; restart completes <30s; portal is functional after restart (all endpoints respond); 3-strikes escalation works; all events logged.
