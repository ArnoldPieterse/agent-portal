# Designer - 10 goals (set 2026-11-23, cycle-14)

Focus: Closed-Loop Autonomy & Fleet Cockpit. Cycle 14 makes the fleet visible and comprehensible: a cockpit that shows what's happening, why it happened, and what happens next.

1. **Cockpit Layout System** - `memory/designer/cockpit-layout.md`: design the responsive layout grid for the Fleet Cockpit. Primary panels: agent status row (top), goal progress column (left), resource gauges (right), decision feed (center-bottom), prediction sidebar (far-right). Define breakpoints, panel priority order, and collapse behavior. Verified: layout spec defines >=5 panels with positions; mobile/tablet/desktop breakpoints specified; panel priority order documented for space-constrained views.

2. **Decision Feed UX** - `memory/designer/decision-feed-ux.md`: design the decision feed UI: vertical timeline with expandable cards. Each card shows: timestamp, agent, trigger summary, action taken, outcome (color-coded: green=success, yellow=rollback, red=escalated). Click to expand full context + evidence chain. Verified: spec defines card states (compact, expanded, error); color coding documented; interaction flow described (hover, click, filter by agent/outcome).

3. **Agent Status Card** - `memory/designer/agent-card.md`: design individual agent status cards showing: name, current model, host, VRAM bar, context bar, current task (truncated), health indicator (dot: green/yellow/red), last-action timestamp. Define states: active, idle, degraded, down. Verified: spec covers 4 health states with distinct visual treatments; VRAM/context bars have threshold colors; card fits in 200x120px minimum.

4. **Fleet Health Heatmap** - `memory/designer/health-heatmap.md`: design a time-series heatmap: rows = agents, columns = 24h in 15-min slots, cell color = health score (green->yellow->red). Tooltip shows exact score + top contributing factor. Click a cell to see what happened at that time. Verified: spec defines color scale with 5+ steps; tooltip content specified; interaction (click -> detail view) described; readable at 1024px width.

5. **Goal Progress Redesign** - `memory/designer/goal-progress-v2.md`: redesign goal progress display for cockpit: per-agent completion bars, cycle-level % prominently shown, at-risk goals highlighted (amber border + predicted miss date), blocked goals show unblock step inline. Verified: spec defines visual treatment for 4 goal states (on-track, at-risk, blocked, complete); at-risk highlighting is distinct from blocked; layout works with 10 goals per agent without scrolling.

6. **Cockpit Theme System** - `memory/designer/cockpit-themes.md`: implement dark/light theme switching for cockpit. All data visualizations (bars, heatmaps, timelines) must be readable in both modes. Define CSS custom properties for each theme; ensure WCAG AA contrast ratios. Verified: both themes defined with complete color palettes; contrast ratio >=4.5:1 for all text in both themes; theme toggle persists across page reloads.

7. **Alert & Notification Design** - `memory/designer/alert-ux.md`: design the alert system UI: severity levels (info/warning/critical) with distinct visual weight, grouping by root cause (not individual alerts), acknowledgment flow (ack -> assign -> resolve), escalation indicator (timer showing when it escalates if unacked). Verified: 3 severity levels defined with distinct visuals; grouping logic documented; ack/assign/resolve flow described; escalation timer behavior specified.

8. **Resource Usage Visualization** - `memory/designer/resource-viz.md`: design VRAM/context/token usage visualizations: per-agent horizontal bars with threshold markers, fleet total as stacked bar, 24h trend line with predicted-breach marker (dashed line extending to where prediction says it'll hit limit). Verified: spec defines bar layout with 3 thresholds (60/80/100%); trend chart includes prediction overlay; breach marker is visually distinct from actual data.

9. **Cockpit Tablet-Responsive Pass** - `memory/designer/tablet-responsive.md`: ensure cockpit is usable at 768px width (tablet landscape): priority panels visible without scrolling, secondary panels in collapsible accordions, touch targets >=44px, no horizontal scroll. Verified: spec defines which panels are primary vs secondary at 768px; accordion behavior described; all interactive elements meet 44px minimum; tested layout has no overflow.

10. **Decision Replay UI** - `memory/designer/decision-replay.md`: design a timeline scrubber for replaying past decisions: horizontal timeline with decision markers, drag to select time range, see what triggered what in sequence, before/after state comparison panels side-by-side. Verified: spec defines scrubber interaction (drag, click, zoom); before/after panel layout described; minimum 5 decisions visible without scrolling at 1024px.
