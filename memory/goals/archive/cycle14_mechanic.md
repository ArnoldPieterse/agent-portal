# Mechanic - 10 goals (set 2026-11-23, cycle-14)

Focus: Closed-Loop Autonomy & Fleet Cockpit. Cycle 14 makes the fleet physically autonomous: models swap themselves, hosts fail over cleanly, and resource imbalance corrects itself without a human touching a terminal.

1. **Model Swap Automation v2** - `python memory/mechanic/model_swap_v2.py`: improve model swap to be atomic and verified: pre-validate target host has sufficient VRAM + context headroom, execute swap with zero-gap (agent responds before old model unloads), post-swap verification (ping agent, confirm correct model loaded). Emit swap log. Verified: 3 swaps executed across different hosts; zero response gap during swap (<2s); post-swap ping confirms correct model; a swap to undersized host is rejected pre-check.

2. **Host Failover Drill Executor** - `python memory/mechanic/failover_drill.py`: automate failover drills on schedule: simulate host unreachable (kill network or stop service), verify agents detect within 60s, migrate to backup hosts, verify all agents respond post-migration. Score the drill. Emit drill results. Verified: 2 drills executed; detection <60s in both; all agents migrated and responding within RTO; no data loss detected post-drill.

3. **Fleet Resource Rebalancer** - `python memory/mechanic/rebalancer.py`: monitor VRAM/context usage across hosts every 5 min; when imbalance exceeds threshold (one host >80% while another <40%), propose migration plan and execute it (swap models to balance load). Log each rebalancing action. Verified: simulated imbalance triggers rebalancing within one check cycle; post-rebalance all hosts within 60-75% range; action logged with before/after metrics.

4. **OOM Recovery Automation v2** - `python memory/mechanic/oom_recovery_v2.py`: improved OOM handling: pre-allocate 10% VRAM headroom on each host, graceful degradation path (reduce context window by 50% before kill), auto-retry with smaller allocation after recovery. Track OOM events and recovery time. Verified: simulated OOM triggers graceful degradation (not hard crash); agent continues at reduced context; full recovery within 120s; event logged with timeline.

5. **Network Partition Detection** - `python memory/mechanic/partition_detect.py`: distinguish between "host is down" (no packets) and "network partition" (packets dropped but host alive). Use multiple probe types (TCP, ICMP, application-level) to classify. Emit different alerts for each case; prevent false failover on temporary partitions. Verified: 3 network conditions simulated (healthy, partition, down); each classified correctly within 30s; no false failover triggered during 60s partition window.

6. **Model Warm-Start Cache** - `python memory/mechanic/warm_cache.py`: maintain pre-loaded model instances on standby hosts for the top-3 most-used models. When a failover is needed, agent connects to warm instance (<5s) instead of loading from scratch (<120s). Track cache hit rate and failover time reduction. Verified: 3 models kept warm on standby; failover to warm model completes in <10s (vs >60s cold); cache hit rate tracked; warm model is verified responsive every 5 min.

7. **Fleet Health Scoring Model** - `python memory/mechanic/health_score.py`: composite health score per host (0-100) combining: CPU load, VRAM usage, network latency, disk I/O, temperature (if available). Weighted formula documented. Trend over time + alert when score drops below 60 or changes by >20 in 5 min. Verified: score computed for all hosts every 5 min; a simulated degradation (CPU spike) drops score by >=15 within one interval; alert fires on threshold breach.

8. **Automated Capacity Planning** - `python memory/mechanic/capacity_plan.py`: predict resource needs for next cycle based on: number of active agents, their model sizes, expected context usage from goal complexity. Flag if current fleet can't handle it. Propose specific scaling actions (which host to add models to, which to offload). Verified: prediction generated for next cycle; a scenario where capacity is insufficient is flagged with specific shortfall; recommended action is concrete (host + model + VRAM needed).

9. **Inter-Service Health Probes** - `python memory/mechanic/service_probes.py`: add health probes between all agent pairs that communicate: verify request/response works, measure latency, detect single points of failure (if removing one host breaks >1 path). Emit connectivity matrix. Verified: probe matrix for all agent pairs generated; a simulated host removal shows which paths break; SPOF identified and reported; probe runs every 2 min.

10. **Post-Incident Auto-Report** - `python memory/mechanic/incident_report.py`: after any incident (OOM, failover, partition, model swap failure), auto-generate a structured report: timeline with timestamps, detected root cause (from probe data), actions taken (automated + manual), recovery time, lessons learned (what could prevent recurrence). Emit to memory/ops/incidents/. Verified: 2 simulated incidents generate complete reports; all sections populated from actual event data; report is <2KB and machine-parseable.
