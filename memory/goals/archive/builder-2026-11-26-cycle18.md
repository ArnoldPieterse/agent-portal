# Builder — Cycle 19 Goals (set 2026-11-26)
Round topic: **Fleet Autonomy Convergence**
Phase: Post-convergence sustainability + self-optimization (fleet at 115/116, maintaining >80% autonomy)

1. **Autonomous Goal Proposer** - `python memory/builder/goal_proposer.py`: read autonomy-score.json trend + intervention patterns + cost data from last 3 cycles; generate 3-5 NEW goal candidates per agent addressing the weakest signal (not inheriting, not ranking existing — generating fresh ideas). Output: memory/ops/proposed-goals-cycle<N>.json with {agent, goals[{title, rationale, target_signal, confidence}]}. Verified: runs on live data without error; generates >=3 distinct goals per agent; no goal matches any entry in closed_topics.json (0 anti-repeat violations); each rationale references a specific metric value.

2. **Token Cost Governor** - `python memory/ops/cost_governor.py`: track token spend per agent per auto-loop pass (from pass logs); if an agent exceeds its budget threshold for 2+ consecutive passes, write a throttle directive to the dispatch queue (reduce max_tokens by 20%, add 30s cooldown between messages). Output: memory/ops/cost-governance.json with {agent, spend_last_3_passes, threshold, throttle_active, action_taken}. Verified: synthetic data triggers throttle at correct threshold; no throttle on under-budget agents; idempotent (re-run doesn't double-throttle); 5 test scenarios pass.

3. **Fleet Topology Recommender** - `python memory/builder/topology_recommender.py`: analyze inter-agent assist patterns from handoff notes (memory/handoffs/) over last N cycles; if agent A assists agent B in >40% of passes, propose structural change (seat reallocation, model upgrade, or goal reassignment). Output: memory/ops/topology-proposal.json with {from_agent, to_agent, pattern_evidence, proposed_change, predicted_impact_pct}. Verified: correctly identifies top-3 assist pairs from synthetic data; proposals are actionable (not vague); 0 false positives on balanced data; runs <5s.

4. **Cross-Cycle Pattern Extractor** - `python memory/builder/pattern_extractor.py`: scan all completed goals (closed_topics.json + goal_ledger verified entries) for recurring success patterns (e.g., "selftest N/N PASS" acceptance criteria correlate with 100% completion rate); build a pattern library. Output: memory/ops/pattern-library.json with {pattern_id, description, source_goal_count, applicability_criteria, historical_success_rate}. Verified: extracts >=5 distinct patterns from existing data; each pattern has >=3 source goals; success rates are computed not hardcoded; idempotent on re-run.

5. **Host Resource Load Distributor** - `python memory/builder/load_distributor.py`: monitor per-host resource metrics (VRAM %, CPU %, memory % from fleet-metrics.jsonl); when a host exceeds 80% sustained utilization for >10min, generate migration recommendations respecting model compatibility constraints (model X only runs on hosts with >=Y GB VRAM). Output: memory/ops/migration-recommendations.json with {agent, from_host, to_host, reason, confidence, vram_required, vram_available}. Verified: correctly identifies overloaded host from synthetic data; respects VRAM constraints (never recommends incompatible target); no recommendation when all hosts <80%; idempotent.

6. **Convergence Sustainability Monitor** - `python memory/ops/sustainability_monitor.py`: after fleet hits 100% goal completion, track whether autonomy score stays >80% for 3+ consecutive cycles; if it drops below 80%, fire alert with root-cause hypothesis (which component of the composite score degraded). Distinct from deceleration_alert.py (which watches VELOCITY) — this watches ABSOLUTE LEVEL post-convergence. Output: append to memory/ops/alerts.jsonl with {ts, type:"sustainability", score, threshold, degraded_component, hypothesis}. Verified: fires on synthetic 79-point score; does NOT fire on 81-point score; correctly identifies which sub-component dropped; idempotent (no duplicate alerts in same cycle).

7. **Goal Completion Risk Predictor** - `python memory/builder/goal_risk_predictor.py`: for each goal accepted into a new cycle, predict completion probability based on: (a) agent's historical success rate on goals of similar complexity, (b) available infrastructure (hosts up, models loaded), (c) goal's dependency chain depth. Output: memory/ops/goal-risk-predictions.json with {goal_id, predicted_completion_pct, confidence_interval, risk_factors[{factor, impact}]}. Verified: predictions correlate with actual outcomes on historical data (Pearson r > 0.5); identifies at least one correct risk factor for known-failed goals; runs <10s on full goal set.

8. **Fleet Auto-Documentation** - `python memory/builder/self_doc.py`: scan all .py files in memory/ + config files; auto-generate architecture doc with dependency graph (which scripts call which), API surface (functions exposed), and data flow (which .jsonl/.json files are read/written). Output: memory/ops/architecture-auto.md updated on every cycle transition. Verified: generated doc matches actual code (spot-check 5 functions); dependency graph has no false edges; file is <300 lines; regenerates idempotently (no diff on re-run with no code changes).

9. **Intervention Taxonomy Builder** - `python memory/builder/intervention_taxonomy.py`: cluster all historical human interventions (from intervention_logger data + decision-log) into categories: infrastructure-failure, goal-mismatch, ambiguity, capacity-exceeded, policy-conflict. Verified: all interventions are classified (0 unclassified); categories are mutually exclusive; each strategy is actionable (specific command or config change); runs on live data without error.

10. **Cycle Token Budget Allocator** - `python memory/builder/budget_allocator.py`: given total token budget for a cycle + per-agent priority scores (from goal_prioritizer output), allocate token budgets per agent proportional to priority-weighted complexity (high-priority + low-complexity = less tokens needed). Output: memory/ops/cycle-budget.json with {agent, allocated_tokens, justification, expected_goals_to_complete}. Verified: allocations sum to total budget; higher-priority agents get >= lower-priority (monotonic); 0 allocation to agents with no open goals; idempotent on re-run.
