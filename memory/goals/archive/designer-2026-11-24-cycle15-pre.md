# Designer - 10 goals (set 2026-11-23, cycle-12)

Focus: Closed-Loop Autonomy & Fleet Cockpit. Cycle-12 progression: cycle 11 made the cockpit ONE coherent closed-loop autonomy instrument; this cycle makes it *adaptive* (density shifts with risk), *forward-looking* (forecast + concurrent goals), and *operable* (emergency brake, live topology, confidence decay) — an operator can trust, intervene in, and trend the fleet without leaving the screen.

1. **Adaptive Information Density (Calm vs. Incident)** - Design two cockpit density modes: "calm" for normal operation shows only aggregate health + active loops; "incident" mode auto-engages when any panel enters critical/degrading, expanding to per-goal detail, incident triage, and intervention points. Transition < 500ms, reversible, preserves scroll on non-critical panels. Produce spec + CSS in ui/cockpit-density.css. Verified: calm mode shows <= 3 primary panels; incident mode auto-triggers on first critical state; transition preserves context; reduced-motion path is instant swap. (verified: ui/cockpit-density.css + ui/cockpit-density.js — recorded 2026-11-24)

2. **Decision Provenance Overlay** - Design the "where did this come from?" overlay: clicking any cockpit data point (health score, risk item, autonomy level) opens a provenance panel showing the chain: which agent made the decision -> which evidence leaves it cited -> when that evidence was last verified. Ties to Archivist's Decision-Knowledge Feedback Loop. Produce spec + markup in ui/cockpit-provenance.html. Verified: every primary data point has a provenance hook; chain renders <= 3 hops deep; stale evidence (>7d) is flagged in the chain; overlay is keyboard-dismissable and screen-reader labeled. (verified: ui/cockpit-provenance.html — recorded 2026-11-24)

3. **Multi-Goal Concurrency View** - Design the view for >= 3 goals in-flight simultaneously: a compact "fleet board" showing each goal's loop-stage as a node on a shared timeline, color-coded by health, spatially grouped by agent. Legible at 1024px without horizontal scroll. Distinct from cycle-11's single-goal loop — this is the multi-goal overview. Produce spec + CSS in ui/cockpit-fleetboard.css. Verified: 5 concurrent goals render without overlap; each goal's current stage identifiable in < 2s; grouping by agent visually distinct from grouping by health; empty state shows "no active goals" calmly. (pointer: memory/designer/acceptance-2-5-9-10-2026-11-19.md) (verified: ui/cockpit-fleetboard.css — recorded 2026-11-24)

4. **Predictive Risk Surface (Forward-Looking)** - Design the forward-looking risk panel: renders next10.json forecast data as a horizontal timeline showing predicted fleet state 1-10 cycles ahead, with confidence bands (high/medium/low) and "predicted all-clear ETA" marker. Ties to Researcher's forecast engine. Produce spec + JS skeleton in ui/cockpit-forecast.js. Verified: forecast renders from real next10.json structure; confidence bands visually distinct; past cycles show actual vs. predicted (calibration); empty forecast shows "insufficient data" not a blank chart. (verified: ui/cockpit-forecast.js — recorded 2026-11-24)

5. **Operator Emergency Brake UX** - Design the intervention pattern for when an operator must override an autonomous action: a prominent but non-accidental "HOLD" control that pauses all pending autonomous actions, shows what was about to happen, and requires explicit confirmation (not a single click) to resume. HOLD state is visually unambiguous fleet-wide. Produce spec + CSS in ui/cockpit-brake.css. Verified: HOLD reachable from any panel without scrolling; activation shows exactly which actions are paused; resume requires deliberate confirmation; HOLD state visible in the autonomy indicator; keyboard-accessible. (verified: ui/cockpit-brake.css — recorded 2026-11-24)

6. **Autonomy Confidence Decay Indicator** - Design how an autonomous decision's confidence degrades visually over time without re-verification: a subtle desaturation or "fading ring" on verified-closed goals that grows with staleness, making old verifications visibly less authoritative than fresh ones. Ties to cycle-11 goal 7 (freshness) but at the *decision* level, not panel level. Produce CSS in ui/cockpit-decay.css. Verified: decay visible after 24h of no re-verification; a re-verified goal snaps back to full confidence; decay rate configurable via data attribute; does not conflict with state-coherence map (cycle-11 goal 5). (verified: ui/cockpit-decay.css + ui/cockpit-decay.js — recorded 2026-11-24)

7. **Fleet Topology Live Graph** - Design the 4-host fleet as a live topology graph: nodes = hosts, edges = model/agent assignments, node size = VRAM utilization, edge thickness = data volume. A host going down desaturates its node and re-routes edges visually. Ties to Mechanic's fleet ops and Orchestrator's capacity governor. Produce spec + JS skeleton in ui/cockpit-topology.js. Verified: 4 hosts render at correct relative positions; simulated host-down desaturates node within 500ms; agent reassignment shown as edge re-routing; graph legible at 768px (simplified mode). (verified: ui/cockpit-topology.js — recorded 2026-11-24)

8. **Cross-Cycle Trend Strip** - Design a persistent horizontal strip showing fleet health + autonomy level across the last N cycles (from cycle_quality.py reports): sparkline-style mini-chart with one dot per cycle, color-coded by overall outcome (all-reached / partial / missed). Gives "how has this been going?" glance without opening a report. Produce spec + CSS in ui/cockpit-trend.css. Verified: >= 5 cycles render; each dot hoverable for detail; trend direction (improving/declining/stable) visually apparent; strip fits within 32px height; works in both light and dark themes. (verified: ui/cockpit-trend.css — recorded 2026-11-24)

9. **Knowledge Impact Surface** - Design the "what knowledge did this decision use?" panel: when a goal closes or reverts, show which memory/ leaves were cited as evidence, their freshness at decision time, and whether any have since been superseded or flagged stale. Ties to Archivist's Decision-Knowledge Feedback Loop and KB Regression Sentinel. Produce spec + markup in ui/cockpit-knowledge-impact.html. Verified: a closed goal shows its cited leaves with timestamps; superseded leaves visually flagged; panel expandable from both loop view and revert view; empty state ("no citations recorded") is explicit. (verified: ui/cockpit-knowledge-impact.html — recorded 2026-11-24)

10. **Cockpit Cognitive Load Budget** - Define and enforce a cognitive load model: at any moment, the operator should identify (a) fleet health, (b) what's in-flight, (c) what needs attention — in <= 5s without reading text. Produce memory/designer/cognitive-budget.md with measurable criteria + audit script (ui/cockpit-load-audit.py) that counts visible text nodes, distinct colors, and interactive elements above the fold at each breakpoint. Verified: doc defines <= 3 primary visual channels above the fold; audit script runs headlessly and reports element count per panel; violation (> threshold) fails the QA gate (cycle-11 goal 9). (verified: memory/designer/cognitive-budget.md + ui/cockpit-load-audit.py — recorded 2026-11-24)

**Through-line:** Goals 1-2 make the cockpit *adaptive* (density shifts with risk, provenance one click away); 3-4 make it *forward-looking and multi-scope* (concurrent goals, predicted future); 5-7 make it *operable and alive* (emergency brake, confidence decay, live topology); 8-10 close the loop on *trust over time* (trend history, knowledge impact, cognitive load enforcement).
