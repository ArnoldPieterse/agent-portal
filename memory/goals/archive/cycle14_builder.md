# Builder - 10 goals (set 2026-11-23, cycle-15)

Focus: Closed-Loop Autonomy & Fleet Cockpit. Cycle 15 builds the intelligence layer on top of cycle-14's execution backbone: the loop learns from outcomes, correlates signals, predicts capacity, and exposes everything as actionable cockpit views.

1. **Closed-Loop Feedback Scorer** - `python memory/builder/loop_scorer.py`: for every completed closed loop (trigger → decision → action → verification), compute an effectiveness score (0-1) based on: time-to-resolution, rollback occurrence, metric delta post-action, and whether the same trigger recurs within 24h. Emit scores to memory/builder/loop-scores.jsonl; maintain a rolling 7-day average per policy rule. Verified: 5 completed loops scored correctly; a loop that triggered rollback scores <0.5; a loop where the same trigger recurred scores <0.3; 7-day averages are present for each policy rule ID.

2. **Adaptive Policy Tuner** - `python memory/builder/policy_tuner.py`: read loop-scores.jsonl + executor-log.jsonl; identify policy rules with rolling-7d score <0.6; propose adjusted thresholds (e.g., widen OOM threshold, extend retry window) as a diff file memory/builder/policy-proposals.json. Never auto-applies — writes proposals for Orchestrator review. Verified: given a synthetic log where one rule consistently scores low, the tuner emits exactly one proposal with old/new values and justification; a healthy rule produces no proposal.

3. **Alert Correlation Engine** - `python memory/builder/alert_correlate.py`: consume alert events from health probes + self-heal reports; group alerts into incidents using temporal proximity (<5min) and host co-location; emit a single incident object {id, host, alerts[], severity, root_cause_hint} to memory/builder/incidents.jsonl instead of N separate alerts. Verified: 3 alerts on the same host within 4 min produce 1 incident; 2 alerts on different hosts >10 min apart remain separate; incident severity is max of constituent alerts.

4. **Fleet Capacity Predictor** - `python memory/builder/capacity_predict.py`: ingest resource metrics from state snapshots (VRAM, disk, agent count); fit a linear trend per host per metric over the last 24h; predict time-to-threshold for each metric; emit predictions to memory/builder/capacity-forecast.json with {host, metric, current, threshold, eta_hours, confidence}. Verified: given synthetic data showing VRAM growing 5%/hour toward 90% threshold, prediction is within ±1h of true crossing; a stable metric shows no warning; output includes confidence interval.

5. **Automated Chaos Drill Scheduler** - `python memory/builder/chaos_drill.py`: on a schedule (configurable, default every 6h), inject a simulated fault into a random non-critical component (kill a test process, spike fake CPU metric, temporarily mark an agent unreachable); verify the remediation pipeline detects and recovers within SLA; log drill result to memory/builder/drill-log.jsonl. Verified: 3 drills executed successfully; each drill's injected fault is detected by the pipeline within 60s; recovery confirmed before next drill; no real service disruption (all targets are sandboxed).

6. **Cockpit Topology Visualizer** - `python memory/builder/topo_view.py`: generate an SVG topology diagram of the 4-host fleet: nodes = hosts (colored by health), edges = active data flows / agent placements, labels = current load %. Serve as a static asset at /api/cockpit/topology.svg; regenerate on every state snapshot. Verified: SVG renders in browser showing all 4 hosts; a host marked red appears red; edge count matches active agent-host assignments from roster; file size <100KB.

7. **Decision Audit Search Index** - `python memory/builder/audit_index.py`: build a full-text search index (SQLite FTS5) over the decision lifecycle log: every trigger, policy match, action, verification result, and rollback event is indexed with timestamp, agent, host, outcome. Expose query API at /api/cockpit/audit?q=<term>&agent=<name>&from=<ts>&to=<ts>. Verified: a query for 'OOM' returns all OOM-related decisions; filtering by agent narrows results; time-range filter works; index builds from 100+ log entries in <5s.

8. **Post-Remediation Auto-Report** - `python memory/builder/post_report.py`: after any remediation action completes (success or rollback), auto-generate a structured markdown post-mortem: timeline, root cause (from alert correlation), actions taken, metrics before/after, lessons learned (from loop score). Write to memory/builder/reports/<timestamp>_<action-type>.md. Verified: 2 simulated remediations produce 2 reports; each contains all 5 sections; metrics section shows actual before/after values from snapshots; report is valid markdown.

9. **Policy Conflict Detector** - `python memory/builder/policy_conflict.py`: scan the policy rule set (from Orchestrator) for rules that could produce conflicting decisions for the same trigger signature: same trigger type + overlapping conditions + different actions. Emit conflict report to memory/builder/conflicts.json with {rule_a, rule_b, trigger_overlap, suggested_resolution}. Verified: given 3 synthetic policies where 2 overlap on 'host_oom' trigger with different actions, exactly 1 conflict is reported; non-overlapping policies produce no conflicts; suggestion field is non-empty.

10. **Cockpit One-Click Runbook Trigger** - `python memory/builder/runbook_trigger.py`: expose a /api/cockpit/runbooks endpoint listing available runbooks with their pre-flight checks; POST /api/cockpit/runbooks/<id>/execute triggers execution via the DAG runner with mandatory pre-flight validation (host reachable, no active alerts on target, disk space sufficient). Returns execution ID + live status URL. Verified: 2 runbooks listed with correct pre-checks; executing a runbook whose pre-check fails returns 409 with reason; successful execution returns 202 + trace ID matching DAG runner log.
