# Mechanic - 10 goals (set 2026-11-23, cycle-9)

Focus: Fleet Intelligence & Adaptive Operations. Cycle-9 builds the predictive ops layer: anticipating failures before they occur, measuring recovery efficiency, and automating preventive maintenance.

1. **Predictive Maintenance Schedule** - `python memory/mechanic/predictive_maint.py`: based on failure history (from incident logs + watchdog events), schedule preventive actions: model reloads before predicted degradation, log cleanup before disk threshold, mirror force-sync after known drift windows. Output: memory/mechanic/maintenance-schedule-YYYY-MM-DD.md with scheduled actions + rationale. Verified: >=3 preventive actions scheduled; each has a historical failure reference; schedule is actionable (exact command + time).

2. **Fleet Recovery Time Tracker** - `python memory/mechanic/mttr_tracker.py`: measure Mean Time To Recovery per failure class (host-down, model-unload, agent-wedge, mirror-drift). Track over cycles; compute trend. Alert if MTTR for any class is increasing. Write to memory/mechanic/mttr-YYYY-MM-DD.md. Verified: >=3 failure classes tracked with >=2 data points each; MTTR calculation is correct; trend direction is accurate.

3. **Resource Usage Forecasting** - `python memory/mechanic/resource_forecast.py`: predict peak VRAM, disk usage, and network I/O 48h ahead from historical patterns (load_trend.jsonl + nvidia-smi snapshots). Use simple linear regression on last 7 days. Alert when predicted peak >80% of capacity. Verified: forecast on historical data has <15% error; alert fires correctly on simulated high usage; report includes confidence interval.

4. **Automated Health Scoring** - `python memory/mechanic/health_score.py`: compute a composite health score (0-100) per host combining: service uptime, VRAM headroom, disk space, network latency, recent error count. Weight each component; produce single number + breakdown. Log to health-scores.jsonl daily. Verified: all 4 hosts scored; weights are documented; a simulated degraded host scores <70; score is stable (not noisy) across runs.

5. **Change Impact Assessment** - `python memory/mechanic/change_impact.py`: before any fleet change (model swap, config edit, schtask modification), assess: blast radius (which agents/hosts affected), rollback plan (exact commands to undo), risk level (low/medium/high). Require assessment output before change proceeds. Write to memory/mechanic/change-assessments.jsonl. Verified: >=3 changes assessed; each has blast radius + rollback + risk; a high-risk change is flagged correctly.

6. **Failure Mode Taxonomy** - Compile all past failures (from incidents, watchdog logs, blockers) into a structured taxonomy: category -> subcategory -> root cause -> frequency -> severity. Write to memory/mechanic/failure-taxonomy.md. Auto-update when new incidents are logged. Verified: >=5 categories defined; all known incidents classified; frequency counts are accurate; doc is machine-parseable (YAML frontmatter per entry).

7. **Capacity Headroom Alerting** - Extend capacity monitoring: alert when PROJECTED usage will exceed 80% within 24h (not just current >85%). Use resource_forecast.py output. Integrate with portal alert banner + escalation chain. Verified: simulated rapid VRAM growth triggers headroom alert before actual breach; alert includes predicted time-to-breach; no false alarms on stable usage.

8. **Operational Playbook Generator** - `python memory/mechanic/playbook_gen.py`: analyze successful recovery patterns from incident logs (what sequence of actions resolved each failure type); auto-generate a runbook for the top-3 most-frequent failure types. Each playbook: trigger condition, step-by-step commands, verification check, rollback if wrong. Write to memory/mechanic/playbooks/. Verified: >=3 playbooks generated; each is executable (commands are valid); follows the pattern from actual successful recoveries.

9. **Fleet Resilience Testing** - `python memory/mechanic/resilience_test.py`: periodic chaos engineering test: randomly select a non-critical component (a model binding, a log file, a schtask) and disrupt it; verify fleet self-heals within SLA. Log results to resilience-tests.jsonl. Verified: >=3 disruption scenarios tested; each verifies recovery within expected time; no data loss during any test; fleet returns to normal state.

10. **Cost-Efficiency Optimization** - `python memory/mechanic/efficiency_audit.py`: track compute time per useful output (agent responses, goal completions, evidence produced). Identify wasted cycles: agents idle >30min, repeated failed probes, redundant verification. Produce optimization recommendations. Write to memory/ops/efficiency-YYYY-MM-DD.md. Verified: >=3 waste categories identified; each has measured cost + recommendation; total potential savings estimated.
